Flujo de Comunicación

  1. Cliente → Ingress: Las peticiones del frontend Angular llegan al NGINX Ingress Controller en el puerto 8080
  2. Ingress → Microservicios: El Ingress enruta las peticiones según el path prefix a cada microservicio
  3. Microservicios → PostgreSQL: Los servicios salen del cluster y se conectan a una única base de datos PostgreSQL via host.docker.internal:5432
  4. Separación Lógica por Schemas:
    • Schema 'public': Tablas de autenticación y usuarios (users, refresh_tokens, email_verification_tokens)
    • Schema 'content': Tablas de contenido multimedia (movie, category, studio, favorite, watchlist, view_history)
  5. Respuesta: Los datos fluyen de vuelta siguiendo el camino inverso

📝 Notas de Implementación

  • Cluster local con kind para desarrollo
  • PostgreSQL ejecutándose como contenedor Docker independiente fuera del cluster
  • Conexión a BD desde los pods usando host.docker.internal:5432
  • Imágenes Docker cargadas localmente con kind load docker-image
  • Variables de entorno configuradas en los manifiestos de Kubernetes
  • Base de datos compartida con aislamiento por schemas
  • Autenticación JWT centralizada en el servicio Auth
