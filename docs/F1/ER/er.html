📊 Diagrama Entidad-Relación - Chapinflix

Base de Datos PostgreSQL con Schemas Separados
Schema public: Autenticación y usuarios
Schema content: Catálogo de películas
Relación: Uno a muchos
Conexión lógica: Sin FK física

📝 Notas Importantes del Diseño

  • Separación por Schemas: La base de datos usa dos schemas para aislar lógicamente los dominios de autenticación y contenido
  • Tipos de ID:
    • Schema public: usa SERIAL (INTEGER auto-incremental)
    • Schema content: usa UUID para mayor escalabilidad
  • Conexión entre schemas: Las tablas favorite, watchlist y view_history tienen user_id (UUID) que se mapea lógicamente a users.id mediante funciones, sin FK física para mantener el desacoplamiento
  • Integridad referencial: Todas las FKs dentro de cada schema tienen CASCADE en DELETE donde corresponde
  • Índices: Se han creado índices en todos los campos de búsqueda frecuente (email, username, slug, etc.)
  • Triggers: view_history tiene un trigger que incrementa automáticamente movie.view_count
  • Stored Procedures: Más de 40 funciones PL/pgSQL manejan la lógica de negocio compleja

✅ Características de Diseño

  • Normalización: Base de datos en 3NF con desnormalización controlada (view_count)
  • Escalabilidad: UUIDs en content schema permiten distribución futura
  • Seguridad: Separación de concerns entre autenticación y lógica de negocio
  • Performance: Índices estratégicos y funciones optimizadas en PostgreSQL
  • Flexibilidad: Soporte para categorías jerárquicas y múltiples relaciones N:M
